## 达梦数据库

- [安装使用手册(DM8)](https://eco.dameng.com/document/dm/zh-cn/pm/installation-introduction.html)
    - [快速上手](https://eco.dameng.com/document/dm/zh-cn/start/index.html)
- **基于 Oracle 改造, 和 Oracle 概念, 语法基本一致**

### 安装

- [下载(达梦数据库管理系统DM | 开发版)](https://www.dameng.com/download/index.html)
    - 测试环境可以下载x86, Win64版本
- 安装说明

```bash
# 下载的一般是 iso 文件, windows 直接双击会自动挂载成一个光驱, 打开文件夹就可以直接运行 setup.exe 安装了
# 设置时区. 如 GTM+8
# 设置 KEY 文件(许可证文件), 开发版本可跳过(内置有可试用的许可证), 生产环境可以进行配置
# 安装完成后初始化数据库 - 初始化参数
    # 字符集选择如 UTF-8， PAGE_SIZE页大小32, 字符串比较大小写敏感(默认勾选, Mysql迁移建议去掉勾选, 同时针对表名和字符串比较), 几个管理用户可以设置统一密码, 开发环境可以勾选测试数据库(DMHR等)安装
    # 字符集, 大小写敏感设置后无法修改
# IDEA连接: 下载达梦 JDBC 驱动, 添加自定义驱动, 创建数据库连接时使用自定义驱动
```
- (可选)多实例配置(端口不一样, 每个实例有自己的 dm.ini 配置文件)
    - 一个 dmserver 进程 + 一套独立的数据目录(包括日志目录) + 一份独立 dm.ini + 一个独立端口
    - 可通过 `达梦数据库配置助手` 创建多个实例 (也支持删除实例)
        - 指定数据库目录: 可设置相同的(之后通过数据库名区分)
        - 数据库标识: 数据库名(DAMENG_ORACLE, DAMENG_MYSQL等), 实例名, 端口号都要设置成不一样的, 勾选路径拼接数据库名。比如: DAMENG_ORACLE 之后对应的就是 DmServiceDMSERVER_ORACLE 的服务
        - 数据库文件: 会自动拼接
        - 初始化参数: 字符集选择如 UTF-8, 字符串比较大小写敏感(默认勾选, Mysql迁移建议去掉勾选)
    - 安装好后修改数据库兼容模式 - 重启数据库
- 兼容模式: dm.ini 中配置 COMPATIBLE_MODE, 可通过`SELECT PARA_NAME, PARA_VALUE FROM V$DM_INI WHERE PARA_NAME = 'COMPATIBLE_MODE';`查看
    - 0：不兼容(默认)
    - 1：兼容 SQL92 标准
    - 2：部分兼容 ORACLE
    - 3：部分兼容 MS SQL SERVER
    - 4：部分兼容 MYSQL
    - 5：兼容 DM6
    - 6：部分兼容 TERADATA
    - 7：部分兼容 POSTGRES
    - 8：部分兼容 DB2
- DM8驱动

```xml
<dependency>
    <groupId>com.dameng</groupId>
    <artifactId>DmJdbcDriver8</artifactId>
    <version>8.1.5.45</version>
</dependency>
```
- JDBC连接
    - URL: `jdbc:dm://localhost:5236`
    - 驱动类: `dm.jdbc.driver.DmDriver`

#### Mysql语法兼容

> 不支持

- `utf8mb4`
- `text/clob` 等类型 Mybatis 返回 map 类型时, 可能导致 Java 序列化失败
    - 原因: Mysql 驱动会自动将 text 类型转换映射为 Java 的 String 类型, 而 DM 驱动返回的是 DmdbClob 类型
    - JdbcTemplate 会自动映射为 String 类型 (可正常序列化)
    - 手动转换: `cast(remark as varchar(32767))` 或 `dbms_lob.substr(remark, 32767, 1)` 转成字符串(一定要加 dbms_lob, 不能直接使用 `substr(remark, 1, 32767)`, 注意参数顺序不一致, 而且 substr 返回的是原字段类型)
    - 基于 Mybatis 映射: `<result column="remark" property="remark" jdbcType="TEXT" javaType="java.lang.String"/>`
- `select date_sub(now(), interval 10 day)` date_sub, date_add 等函数, interval 关键字
    - `select now() - 10;` now() 也可以用 sysdate 代替
    - `select dateadd(DAY, -10, now());`
    - 支持 `select str_to_date('2000-01-01 10:22:43', '%Y-%m-%d %H:%i:%s'), date_format(now(), '%Y-%m-%d %H:%i:%s');`
- `group_concat(t.name)`
    - listagg 代替: 推荐使用; 长度有限制, 超长报错; 如: `listagg(t.name)` 或排序为 `listagg(t.name) within group (order by t.id)`
    - wm_concat 代替: 但是会返回 TEXT 类型, 可使用如 `cast(wm_concat(t.name) as varchar(32767))`转成字符串
    - xmlagg 代替: 长度无限制; 映射到 Java可能是 CLOB 类型; 不支持内部使用 distinct
- `""` 问题
    - DM8 双引号在DM8中表示对象名/标识符
    - 比如 `insert test(id, name) values('1', "hello");` 会报错
- `||` 问题
    - DM8 中 `||` 为字符串拼接符, 逻辑或只能用 `or` (mysql两种都支持)
    - 比如 `select if(t.name != '' || t.name != NULL, t.name, '-NA-') from test` 会报错, 用 `or` 代替即可
- `force index, use index, ignore index` 索引 Hint
    - 参考 Oracle 索引 Hint 写法. 如 force index, use index 改写成: `select /*+ index(user_info idx_user_name) */ * from user ...`; ignore index 使用 no_index

> DM8兼容模式支持

- `&#123;` 反引号, DM8兼容模式支持

> 支持

- `limit 1,10` 支持

### 数据库特性

- 和 Oracle 比较
    - 数据文件 DBF, **单实例单库多模式(表空间-用户), 支持多实例**
    - 不支持 VARCHAR2 类型, 只支持 VARCHAR 类型, Oracle 迁移需要把字段长度扩充x2
    - LOB表空间
        - 普通数据段, 索引段会自动进用户表空间
        - 如果不定义 LOB 字段表空间则 LOB 默认进 SYSTEM; DM 的 TEXT LONGVARCHAR CLOB BLOB 底层都可能走 LOB 表空间
        - 修改方式

        ```sql
        CREATE TABLESPACE LOB_TS DATAFILE '/dmdata/LOB_TS.dbf' SIZE 1024;

        -- 定义字段的显示定义 LOB 的表空间
        CREATE TABLE test (
            id INT,
            content CLOB
        )
        TABLESPACE USER_TS -- 普通数据段, 索引段表空间
        LOB(content) STORE AS (TABLESPACE LOB_TS); -- LOB 字段表空间

        -- 已经建好的可以进行迁移(如果是 Mysql 迁移到 DM 则一般是进了 SYSTEM 表空间)
        ALTER TABLE test MOVE LOB(content) STORE AS (TABLESPACE LOB_TS);
        ```
- 是否区分大小写
    - `select para_name, para_value from v$dm_ini where para_name= 'GLOBAL_STR_CASE_SENSITIVE';` 查看是否区分大小写(0 不区分)
    - 表名/字段名: 默认不区分, 创建数据库实例的时候可配置(创建好后无法修改)
        - SQL 语句书写和 Oracle 类似
    - 字符串比较: 默认区分
        - `ALTER SESSION SET CASE_SENSITIVE = TRUE | FALSE;` 设置当前会话为大小写敏感(只正对字符串比较, 不针对表名/字段名)
        - 在查询项添加 BINARY 前缀区分大小写: `where BINARY t.name = 'test'` (写成 `where t.name = BINARY 'test'` 也可以) 或 `join t_class c on BINARY c.name = t.name` 但是可能会导致索引失效
        - 使用 `where HEX(t.name) = HEX('test');` 但是可能会导致索引失效
    - **DM 只能基于实例设置是否大小写不敏感(不能基于表/字段单独设置)，设置之后无法修改**
